# WPS「公文主体」实测规则

测量对象为 macOS WPS Office 12.1.28496 的 AI 公文排版「公文主体」。使用仓库的虚构通知，通过 WPS 应用该模板、保存 DOCX，并从 WPS 原生打印流程导出 PDF 取样。`assets/wps-body-format.json` 保存提取的版式规则，不含字体或应用程序。

## 原始模板

| 项目 | WPS 实测值 |
|---|---|
| 纸张 | A4，11906 × 16838 twips |
| 页边距 | 上2098、下1984、左1587、右1474 twips |
| 页眉/页脚距离 | 851 / 1417 twips |
| 标题 | 方正小标宋简体，22pt，居中，固定36pt行距 |
| 标题后空段 | 固定15pt行距 |
| 正文 | 仿宋_GB2312，16pt，固定28pt行距，首行2字，两端对齐 |
| 正文字距 | −0.3pt；西文 Times New Roman |
| 一级标题 | 黑体16pt；首行缩进；固定28pt行距 |
| 二级标题 | 楷体_GB2312 16pt；固定28pt行距 |
| 三级标题 | 仿宋_GB2312 16pt；固定28pt行距 |
| 文档网格 | linesAndChars，linePitch579、charSpace15 |
| 附件 | 前留一空段；left1540、hanging924 twips |
| 署名 | 右对齐，右缩进864 twips |
| 日期 | 右对齐，right880、rightChars400 |
| 页码 | 宋体14pt，动态PAGE字段，奇右偶左，形如“— 1 —” |

固定行距与网格的关系以 WPS 实际页面为准。源文档的默认段后距不得污染上述规则。标题后及附件前由模板补充的空段会计入核验报告，原文的空段仍保留。

## 实际字体

这次 WPS 运行时使用了字体映射。相同的字体名称与相同的实际字形应分开核对：

| 模板字体名 | 这次 WPS 实际使用的字族 |
|---|---|
| 方正小标宋简体 | HYShuSongErKW / 汉仪书宋二KW |
| 仿宋_GB2312 | FangSong_GB2312 / 仿宋_GB2312 |
| 黑体 | HYZhongHeiKW / 汉仪中黑KW |
| 楷体_GB2312 | HYKaiTiJ / 汉仪楷体简 |
| 宋体 | HYShuSongErKW / 汉仪书宋二KW |
| Times New Roman | Times New Roman |

脚本检查实际字族并在报告中记录解析结果。所需字体由使用者合法安装；缺少时可生成保留字体要求的 DOCX，视觉核验等待字体补齐。发布包不附字体。普通备选字体属于另一个版式方案，不能作为本次同字体核验的结果。

## 原文保留

WPS 对示例自动识别时，在一级标题后插入空格，且把署名重复填入日期位置。技能仅提取排版规则，按原文保留标题编号、署名和日期。原生对照稿仅校正这几处文字识别错误，保留 WPS 的版式。

## 交付核验

最终 DOCX 应与预览使用相同的字体与版式表达。遇到 GenOffice 对 WPS XML 表达的兼容差异，采用可在 GenOffice 直接打开的等效表达，并在报告记录适配；不以另一个临时排版文件的截图代替交付文件核验。

当前为 **v1.1.0-beta.2 校准版**。单页通知与七页长文的页数、正文断行一致；849 × 1200 对照中，0.11.919 的单页行顶部相差 0–2px，日期最左侧字形相差 4px，抽查页码边界相差 0–1px。0.12.29 已复验相同样稿，抽查正文与旧版逐像素一致，日期和页码字形边界相差 1–2px。含西文或数字的主标题、长附件、复杂对象与其他字体版本需追加同文验收。

GenOffice 兼容处理包括：明确零段前/段后距及固定行距、使用实际字族、纯中文标题的西文字体槽度量修正、页码奇偶定位与垂直偏移补偿。保留 WPS 默认标点设置，额外强制压缩会改变断行。

完整方法、原图和测量数据见 [GitHub 同文验收记录](https://github.com/Bohanfree/genoffice-official-typeset-skill/blob/main/docs/wps-calibration.md)。每份新输出仍需查看实际页面，报告中的 `visualParity: not-verified` 表示该文件尚待视觉验收。
